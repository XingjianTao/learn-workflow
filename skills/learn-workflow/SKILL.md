# Learn Workflow

Teach skill selection and artifact handoffs through fictional practice.

## Load

Read the selected definition and checkpoint. If none is selected, offer the bundled [reading-club lesson](references/reading-club.md). A usable lesson has a version, author/user approval, fictional case, stage contracts/routes, exercises/rubrics and a transfer challenge. Route drafts or missing decisions to `build-workflow` or the author; do not invent them or construct a workflow from installed skills.

## Teach

Introduce the fictional goal, simulation mode and short path in the learner's language. Follow the fixed branches; do not force every skill into every task.

1. Show the current input, why this role fits, and the stage's short example without giving away the exercise answer.
2. Ask **one exercise**, then wait. Use ordinary conversation or a dedicated quiz tool, not an approval form.
3. Evaluate the answer against the rubric, accepting equivalent reasoning. Give specific feedback; wrong or incomplete answers stay here for a retry.
4. Carry the accepted artifact forward with its identifiers, constraints and unresolved items. Label any supplements taken from the definition.

Record `demonstrated`, `self-reported`, `skipped` or `needs-practice` accurately. A requested skip uses a labeled reference artifact, not an invented learner answer. Finish with the fixed transfer challenge and report evidence and gaps; presenting a lesson does not prove mastery.

## Preserve boundaries

Mark mock code/tests/releases **SIMULATED**. Rehearsal may save learning records but never execute component skills or external actions. A request for real work switches to the normal execution workflow with its concrete target and authorization.

Use [checkpoint guidance](references/checkpoint.md) to save/resume. Workflow changes return to authoring as a separate version; never silently change an active lesson. Source inspection and role simulation do not establish installation or real execution.
